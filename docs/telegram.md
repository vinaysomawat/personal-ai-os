# Telegram bots

One bot per module (`TELEGRAM_BOT_TOKEN_*`): **Daily** (module key `planner`, `TELEGRAM_BOT_TOKEN_PLANNER`, webhook `/api/telegram/planner`), **Finance**, **Health**, **Astrology** — one webhook route (`src/app/api/telegram/[module]/route.ts` → `src/features/telegram/handler.ts`).

**Pipeline:** only `TELEGRAM_ALLOWED_CHAT_ID` is accepted → voice is transcribed (`transcribeVoice()` → shared `transcribeAudio()`, Groq `whisper-large-v3-turbo`, `GROQ_API_KEY`) → photos go to Finance (receipt) / Health (meal) via `VISION_PROMPT` → the module's optional `handleCommand` for slash commands (Daily: `/quiz`; deterministic, so it runs before the cap and is never taken as a drill answer) → a daily call cap (`TELEGRAM_DAILY_AI_CAP`, default 300, counted from `telegram_logs`) → the module's optional `preIntercept` (Daily: a pending drill answer) → intent parsing (`telegram_intent`, Haiku; today's IST date injected; may return an array of actions) → `execute()` per action → reply → `telegram_logs`. A budget-exhausted parse replies with a daily or monthly "budget used up" message instead of the help menu.

**Undo:** `undo_last` per bot; "↩️ Undo" buttons on created rows encode the row id (`undo:<table>:<id>`, allowlist `UNDOABLE_TABLES` in `src/lib/telegram/buttons.ts`: expenses, loans, investments, workouts, food_log). Logging an expense warns when its category is over / ≥90% of budget.

**Webhook subscriptions:** `scripts/setup-webhooks.mjs` (run with `node --env-file=.env.local scripts/setup-webhooks.mjs <app url>`) subscribes every bot to `message`, `callback_query` (button taps) and `poll_answer` (quiz polls), and registers each bot's `/` menu with `setMyCommands` (Daily: `/quiz`). Telegram only delivers subscribed update types, so re-run it whenever either list changes. Non-Undo button taps go to the module's `handleCallback(data, db, userId, io)`, which drives the Telegram side effects itself through `io` (`ack`, `clearButtons`, `send`, `sendHtml`, `sendPoll`) so it can acknowledge a tap before slow work; `poll_answer` goes to the module's `handlePollAnswer`, gated on the answering user's id (equal to the chat id in a private chat).

## Quiz (Daily bot)

`src/features/telegram/quiz.ts` (command, picker, routing), `quiz-build.ts` (building a quiz), `quiz-run.ts` (running and scoring it). **Scored on Telegram only**: it reads `coding_questions` but never writes `question_progress`, readiness, coverage or any Prep block, and nothing in the web app reads its tables.

- **`/quiz`** (also `/quiz@<bot>`) → "Pick a category" with inline buttons, two per row: JS & React (`quiz`), System design, FE architecture, Backend & APIs, AI engineering, AI-native, Angular, 🎲 Mixed (`callback_data` `quiz:cat:<category>`). Coding categories aren't offered; behavioral and resume questions only appear as descriptive questions in Mixed. One tap starts the quiz and removes the buttons.
- **Building** (`buildQuizSession()`): 8 slots (`slotPlan()`). A single category = 6 multiple choice + 2 descriptive, all from it. Mixed = 6 multiple choice from 6 different categories, 1 descriptive from behavioral/resume, 1 descriptive from any quiz category. `pickSlots()` skips questions quizzed in the last 3 days and prefers ones whose latest quiz answer was wrong or not "Got it", otherwise random, never repeating within a quiz. Each bank question's quiz version is stored in `quiz_items` (one per question and kind) and reused forever; only missing ones are generated, by `quiz_generate` (one call per kind, in parallel). `parseGenerated()` drops anything malformed or over Telegram's limits and shuffles the 4 options in code. An active quiz started under 90 s ago means a retry or double tap ("⏳ Your quiz is already on its way."); an older one is marked `abandoned`. The one-active-per-user index rejects a racing second insert the same way. If nothing could be generated, the reply says so (or that the AI budget is used up).
- **Multiple choice**: a native Telegram quiz poll (`sendPoll`, `type: quiz`, non-anonymous), "Q1/8 · <question>", with the note as the poll's explanation. Telegram shows ✅/❌ and the note on tap; the bot then records `correct` and sends the next question.
- **Descriptive**: an HTML message, "✍️ Q7/8 · Descriptive", the question, and the key points as a `<tg-spoiler>` (tap to reveal), with self-grade buttons ✅ Got it (1) / 🟡 Partly (0.5) / ❌ Missed (0) (`quiz:g:<answer id>:<g|p|m>`). Grading removes the buttons and sends the next question.
- **One question at a time**: question N+1 goes out only after N is answered. Every write that moves the quiz forward is conditional (answer only if `answered_at` is still null, advance only if `current_index` is still N, finish only if still `active`), so a redelivered update, a double tap or an answer to an abandoned quiz's poll does nothing. A question Telegram rejects is skipped and not scored.
- **Score** after the last question: "🏁 <category> quiz — 5.5/8 (69%)", "Multiple choice 4/6 · Descriptive 1.5/2", then "🎯 Clean sweep" on a perfect score or, in Mixed, "Weakest:" with up to 3 categories that lost the most points.
